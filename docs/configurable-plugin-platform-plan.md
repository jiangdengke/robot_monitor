# 机器人二开管理系统可配置化与轻插件化改造方案

## 1. 业务结论

当前系统不建议继续按“国航休息室迎宾后台”演进，建议升级为“机器人二开项目可配置交付平台”。

推荐路线是：**每个项目独立部署一套系统，通过高配置化复用公共能力，通过轻插件化承接项目差异**。

这条路线的核心判断：

- 公共后台能力平台化，避免每个项目复制一套系统再硬改。
- 项目名称、菜单、术语、字段、任务模板、模块开关等高频交付差异配置化。
- 机器人厂家、复杂业务流程、外部系统对接、复杂页面和统计口径插件化。
- 暂不建设运行时热插拔插件平台，避免把项目拖入低代码平台或插件市场建设。

## 2. 已确认前提

1. **部署模式**：每个项目独立部署一套系统，不做一套系统同时服务多个客户的多租户平台。
2. **场景边界**：新项目不限定为迎宾场景，需要支持其他机器人二开项目。
3. **配置程度**：配置能力需要偏高，但仍要保留代码插件承接复杂差异。
4. **现有项目定位**：国航休息室迎宾不再作为系统本体，而是沉降为第一个项目模板。

## 3. 目标定位

系统目标不是做一个完全通用的低代码平台，而是做一套面向机器人二开交付的后台平台。

目标能力包括：

- 快速生成一个新项目的后台管理系统。
- 通过配置调整系统标题、菜单、业务叫法、页面字段和任务模板。
- 通过插件切换不同机器人厂家、场景业务、统计口径和外部系统集成。
- 保持每个项目独立部署，降低数据隔离、权限隔离和插件热加载复杂度。

## 4. 总体架构

建议拆成四层：

```text
平台底座层
  登录、权限、用户、日志、文件、资源、机器人基础管理、设备基础管理、知识库、部署能力

配置中心层
  项目配置、模块开关、业务术语、菜单、页面字段、字典、任务模板、统计项

轻插件层
  场景业务插件、机器人厂家插件、外部系统集成插件、统计插件、复杂前端页面插件

项目模板层
  lounge-greeting、exhibition-guide、park-patrol、custom-project 等模板
```

推荐理解方式：

- **配置**解决“交付时经常改，但逻辑相对固定”的差异。
- **插件**解决“配置表达不清楚，必须写代码”的差异。
- **模板**解决“新项目怎么快速初始化”的问题。

## 5. 平台底座层

平台底座层是所有项目共享的能力，不应该绑定具体客户或具体场景。

建议保留或沉淀这些能力：

- 登录认证。
- 用户、角色、权限。
- 菜单权限。
- 登录日志、操作日志。
- 文件上传、下载和资源管理。
- 图片、音频、视频素材管理。
- 机器人基础档案。
- 设备基础档案。
- 知识库基础能力。
- 系统配置。
- 基础统计框架。
- Docker 单镜像部署能力。
- API 安全和鉴权能力。

底座层的原则：少改、稳定、通用，不承载具体项目的业务规则。

## 6. 配置中心层

配置中心层是本次改造的重点。配置程度需要高一点，但要控制边界。

### 6.1 项目基础配置

用于定义一个独立部署项目的基本信息。

建议配置项：

- 项目名称。
- 项目编码。
- 客户名称。
- 系统标题。
- Logo。
- 主题色。
- 首页路由。
- 默认语言。
- 是否启用地图。
- 是否启用数字孪生。
- 是否启用知识库。
- 是否启用统计分析。
- 默认机器人厂家。

### 6.2 模块开关

用于控制一个项目启用哪些能力。

示例：

```text
enableKnowledge=true
enableDigitalTwin=true
enableStatistics=true
enableRobotControl=true
enablePatrol=false
enableGreeting=false
```

模块开关影响：

- 前端菜单是否展示。
- 后端接口是否开放。
- 首页卡片是否展示。
- 统计指标是否启用。
- 任务模板是否可选。

### 6.3 业务术语配置

把“国航休息室迎宾”的固定叫法抽出来，支持不同项目使用不同业务语言。

| 通用概念 | 国航休息室项目 | 展厅讲解项目 | 园区巡检项目 |
| --- | --- | --- | --- |
| space | 贵宾室 | 展厅 | 园区 |
| area | 功能区 | 展区 | 巡检区域 |
| point | 点位 | 讲解点 | 巡检点 |
| task | 任务 | 讲解任务 | 巡检任务 |
| visitor | 旅客 | 访客 | 人员 |
| event | 业务事件 | 讲解事件 | 巡检事件 |

改造后，页面标题、菜单、按钮、表单标签、统计名称优先从术语配置读取。

### 6.4 菜单配置

不同项目可以使用不同菜单结构。

菜单配置建议包含：

- 菜单编码。
- 菜单名称。
- 路由地址。
- 图标。
- 排序。
- 所属模块。
- 权限标识。
- 是否启用。
- 是否需要插件页面。

菜单配置示例：

```text
首页
机器人管理
设备管理
任务管理
知识库
统计分析
数字孪生
系统管理
```

项目模板可以预置一套菜单，部署时允许按项目微调。

### 6.5 页面配置

对标准 CRUD 页面做高配置化。

页面配置建议包含：

- 页面编码。
- 页面名称。
- 所属模块。
- 接口地址。
- 查询条件。
- 表格字段。
- 表单字段。
- 字段类型。
- 是否必填。
- 默认值。
- 枚举字典。
- 校验规则。
- 新增、编辑、删除、导入、导出开关。
- 按钮权限。
- 排序规则。
- 详情页展示规则。

适合配置化的页面：

- 区域管理。
- 点位管理。
- 设备管理。
- 机器人管理。
- 素材管理。
- 任务模板。
- 字典配置。
- 知识库分类。
- 统计明细列表。

不建议完全配置化的页面：

- 数字孪生大屏。
- 地图编辑器。
- 机器人实时控制。
- 复杂统计看板。
- 第三方系统联动页面。

这些页面应通过插件承接。

### 6.6 任务模板配置

任务模板是机器人项目复用的核心。

建议抽象为：

- 任务类型。
- 任务名称。
- 触发方式。
- 执行机器人。
- 执行点位。
- 动作序列。
- 播报内容。
- 素材资源。
- 超时时间。
- 失败策略。
- 是否循环。
- 是否需要人工确认。
- 是否需要外部系统回调。

示例：

```text
迎宾任务：
人员到达 -> 播放欢迎语 -> 引导到指定区域 -> 记录服务事件

讲解任务：
到达讲解点 -> 播放讲解音频 -> 等待确认 -> 前往下一个讲解点

巡检任务：
按路线巡航 -> 到点拍照 -> 检测异常 -> 上报巡检记录
```

第一阶段建议做“可配置任务模板”，不建议直接引入完整流程引擎。

### 6.7 字典和枚举配置

业务枚举不应散落在代码里。

建议统一配置：

- 机器人状态。
- 设备类型。
- 任务类型。
- 任务状态。
- 事件类型。
- 资源类型。
- 业务区域类型。
- 外部系统类型。

## 7. 轻插件层

轻插件化用于解决配置无法优雅表达的差异。

这里的插件不是运行时上传 jar 或 zip 的热插拔插件，而是“代码内置、模块隔离、部署时启用”的轻插件。

### 7.1 场景业务插件

用于承接不同项目场景的专属逻辑。

示例：

```text
lounge-greeting-plugin      休息室迎宾
exhibition-guide-plugin     展厅讲解
park-patrol-plugin          园区巡检
hotel-service-plugin        酒店服务
mall-guide-plugin           商场导览
custom-project-plugin       定制项目
```

场景插件可以提供：

- 默认菜单。
- 默认页面配置。
- 默认任务模板。
- 默认统计指标。
- 专属接口。
- 专属业务规则。
- 专属前端页面。

### 7.2 机器人厂家插件

机器人二开项目最需要这一层。

主系统定义统一机器人能力接口：

```text
获取机器人状态
下发导航任务
停止当前任务
语音播报
返回充电
获取地图
获取点位
获取电量
获取任务进度
接收机器人事件
```

不同厂家插件实现同一套接口：

```text
mock-robot-provider
provider-a-robot-plugin
provider-b-robot-plugin
provider-c-robot-plugin
```

业务代码只调用统一接口，不直接依赖具体厂家协议。

### 7.3 外部系统集成插件

不同项目可能对接不同客户系统。

可插件化的集成包括：

- 会员系统。
- 门禁系统。
- 预约系统。
- 航班系统。
- 园区平台。
- 酒店 PMS。
- 企业微信。
- 钉钉。
- 告警平台。

主系统只保留集成配置、调用日志和统一错误处理，具体协议放到插件里。

### 7.4 统计报表插件

统计口径通常随项目变化，建议插件化。

示例指标：

- 迎宾次数。
- 引导次数。
- 问答次数。
- 讲解完成率。
- 巡检完成率。
- 异常数量。
- 设备联动次数。
- 机器人在线率。
- 任务失败率。

主系统提供统计查询框架和展示容器，具体统计口径由插件注册。

### 7.5 前端页面插件

复杂页面不建议通过页面字段配置硬生成。

适合前端插件承接：

- 数字孪生页面。
- 地图点位编辑器。
- 机器人实时控制台。
- 巡检看板。
- 讲解路线编辑器。
- 项目大屏。

主系统负责菜单、权限和页面挂载，插件负责具体页面实现。

## 8. 项目模板层

项目模板用于快速初始化新项目。

建议模板目录或配置包包含：

```text
project-templates/
  lounge-greeting/
    project.json
    modules.json
    terms.json
    menus.json
    pages/
    tasks/
    statistics.json
  exhibition-guide/
    project.json
    modules.json
    terms.json
    menus.json
    pages/
    tasks/
  park-patrol/
    project.json
    modules.json
    terms.json
    menus.json
    pages/
    tasks/
```

部署新项目时选择模板，然后导入默认配置，再按客户现场微调。

当前国航休息室迎宾建议沉降为：

```text
模板编码：lounge-greeting
模板名称：休息室迎宾
包含模块：贵宾室、区域、机器人、任务、准入准出统计、数字孪生
```

## 9. 推荐数据模型

第一阶段可以先新增配置表，不要直接推翻现有业务表。

建议配置表包括：

```text
project_config             项目基础配置
module_config              模块定义
project_module_config      项目启用模块
business_term_config       业务术语
menu_config                菜单配置
page_config                页面配置
page_field_config          页面字段配置
dictionary_config          字典配置
task_template_config       任务模板
robot_provider_config      机器人厂家配置
plugin_registry            插件注册表
integration_config         外部系统集成配置
statistics_item_config     统计指标配置
```

由于每个项目独立部署，第一阶段不强制引入 `tenant_id`。如果后续变成多客户共用一套系统，再单独设计租户隔离。

## 10. 前后端改造方式

### 10.1 后端

建议新增平台配置接口：

```text
GET /platform/bootstrap
GET /platform/modules
GET /platform/menus
GET /platform/terms
GET /platform/pages/{pageCode}
GET /platform/task-templates
```

前端启动后先拉取 `bootstrap`，再决定系统标题、菜单、模块和页面配置。

机器人能力建议定义统一网关：

```text
RobotProviderGateway
  getStatus()
  navigateTo()
  stopTask()
  speak()
  returnToCharge()
  getMap()
  getPoints()
```

不同机器人厂家通过 Spring Bean 或配置开关选择实现。

### 10.2 前端

前端建议形成三类页面：

1. 固定平台页面：登录、用户、角色、日志、系统配置。
2. 配置化 CRUD 页面：区域、点位、设备、机器人、素材、任务模板等。
3. 插件页面：数字孪生、地图编辑器、机器人控制台、复杂统计大屏。

前端启动流程建议：

```text
读取 token
请求 /platform/bootstrap
加载项目标题、主题、术语
根据菜单配置生成路由和菜单
根据模块开关决定页面是否可访问
进入业务页面
```

## 11. 分期落地计划

### 第一阶段：去国航化和配置中心雏形

目标：先让系统从“国航迎宾后台”变成“可配置项目后台”。

交付内容：

- 项目基础配置。
- 模块开关。
- 业务术语配置。
- 菜单配置。
- 标准 CRUD 页面字段配置。
- 国航迎宾模板化。

验收标准：

- 修改配置后，可以切换系统标题、Logo、菜单和业务术语。
- 至少一个标准 CRUD 页面由配置驱动展示字段和表单字段。
- 国航休息室迎宾仍可通过模板恢复当前使用效果。
- 已新增 `exhibition-guide` 示例模板，用于验证非迎宾项目可以通过配置切换系统标题、菜单、术语和标准 CRUD 页面文案。
- 前端无后端配置可用时的默认回退已改为通用机器人二开项目，不再把国航休息室作为系统本体默认值。

### 第二阶段：机器人厂家适配插件

目标：把机器人二开差异从业务代码中隔离出来。

交付内容：

- 统一机器人能力接口。
- Mock 机器人插件。
- 当前项目机器人适配插件。
- 厂家配置和启用开关。

验收标准：

- 业务任务只调用统一机器人接口。
- 切换机器人厂家配置时，不需要修改业务页面。

### 第三阶段：场景插件和任务模板

目标：支持非迎宾类机器人项目。

交付内容：

- 场景插件注册机制。
- 任务模板配置。
- 插件默认菜单和默认页面配置。
- 至少新增一个非迎宾模板作为验证样例。

验收标准：

- 可以通过模板初始化一个非迎宾项目。
- 新项目不出现强绑定“贵宾室”“旅客”“迎宾”的系统文案。

### 第四阶段：统计、集成和复杂页面插件

目标：承接客户项目中的复杂差异。

交付内容：

- 统计指标插件。
- 外部系统集成插件。
- 数字孪生或地图类复杂页面插件。

验收标准：

- 不同项目可以启用不同统计指标。
- 外部系统对接不污染平台底座。
- 复杂页面可以通过菜单配置挂载。

## 12. 不建议第一阶段做的事情

这些事情风险高、周期长，暂不建议作为第一阶段目标：

- 运行时上传 jar 包或 zip 包的热插拔插件系统。
- 完整低代码页面设计器。
- 完整流程引擎。
- 多租户数据隔离平台。
- 一次性重构所有历史表。
- 全部页面都改成动态生成。

## 13. 主要风险和控制方式

### 风险一：配置化过度

如果把所有逻辑都做成配置，系统会变成难维护的低代码平台。

控制方式：字段、菜单、术语、模板走配置；复杂业务、厂家协议、复杂页面走插件。

### 风险二：插件粒度过细

如果每个按钮、每个字段都做成插件，会导致维护成本上升。

控制方式：插件按业务场景、厂家、集成、统计、复杂页面划分，不按零碎控件划分。

### 风险三：现有国航业务被破坏

直接去国航化可能影响当前已可运行功能。

控制方式：先把国航迎宾固化为模板，保证模板导入后能恢复当前业务效果。

### 风险四：数据库初始化影响部署

当前项目启动初始化脚本存在重建表风险。

控制方式：后续部署改造时，应区分演示初始化和生产迁移，不让生产库默认执行重建脚本。

## 14. 给领导汇报口径

可以用以下口径汇报：

> 当前系统会从单一的国航休息室迎宾后台，升级为机器人二开项目可配置交付平台。后续每个项目仍独立部署，避免多租户复杂度；通用能力沉淀为平台底座，菜单、术语、字段、任务模板等交付差异走配置；机器人厂家、复杂页面、外部系统和统计口径走轻插件。这样既能提高复用率，又不会把系统做成过重的低代码平台。

## 15. 下一步最小动作

建议下一步先做“第一阶段：去国航化和配置中心雏形”的详细设计。

最小工作包：

1. 梳理当前代码中所有国航、休息室、迎宾、旅客等强绑定概念。
2. 定义项目配置、模块开关、业务术语、菜单配置、页面配置的数据结构。
3. 选一个现有 CRUD 页面做配置化试点。
4. 把当前国航迎宾沉降为 `lounge-greeting` 模板。
5. 用一个非迎宾样例模板验证配置复用能力。

## 16. 当前已落地的第一步

当前已经先完成“平台启动配置闭环”：

- 后端提供 `GET /platform/bootstrap`。
- 前端启动时读取 bootstrap，并以静态菜单和标题作为失败回退。
- 默认国航休息室配置已沉降为 `lounge-greeting` 模板文件。
- 模板默认位置为 `backend/src/main/resources/platform/templates/lounge-greeting/bootstrap.json`。
- 可通过 `PLATFORM_BOOTSTRAP_LOCATION` 指向其他 `classpath:` 或 `file:` 模板位置，适配每个项目独立部署。
- 平台启动配置已支持数据库覆盖：`project.platform_bootstrap_config` 中存在启用的 `config_json` 时优先返回数据库配置；无配置、查询失败或 JSON 解析失败时继续回退模板文件。
- 系统管理中已增加“平台配置”最小维护入口，可保存完整 bootstrap JSON；当前仍不做字段级低代码编辑器。
- `lounge-greeting` 模板已包含页面级配置试点：`pages.dept`、`pages.area`、`pages.region`、`pages.device`、`pages.robot`、`pages.task`、`pages.image`、`pages.audio`、`pages.robotAudio`、`pages.complaint`，用于驱动现有标准 CRUD 页面的标题、描述、表格列、查询项、表单字段和默认值。
- 前端“贵宾室配置”“功能区管理”“区域管理”“设备管理”“机器人配置”“任务配置”“图片管理”“音频管理”“机器人音频”“投诉记录”页面已改为优先读取模板页面配置，接口动作和现有静态配置仍作为回退。
- 系统管理、日志管理、监控任务和告警统计等平台底座 CRUD 页面已接入同一套页面配置合并能力；默认不写入业务模板，避免项目交付配置误改平台底座页面。
- 前端无后端配置可用时的默认回退已改为通用机器人二开项目，不再把国航休息室作为系统本体默认值。
- 前端菜单、直达路由和首页快捷入口已按 `modules` 开关过滤，关闭模块后对应页面不再作为项目界面展示或访问。
- 已新增 `exhibition-guide` 示例模板，可通过 `PLATFORM_BOOTSTRAP_LOCATION=classpath:platform/templates/exhibition-guide/bootstrap.json` 验证非迎宾项目的标题、菜单、术语和标准 CRUD 页面文案切换。
- 在舱记录和准出记录页面已接入页面配置合并能力，国航场景继续由 `lounge-greeting` 模板恢复，非迎宾模板可通过模块关闭或菜单调整隐藏相关页面。
- 后端项目自有源码已完成 Kotlin 全量迁移：Controller、Service、DTO、鉴权配置、全局异常处理和仓储扩展均已迁移到 `backend/src/main/kotlin`，`backend/src/main/java/org/jdk/project` 不再保留手写 Java；jOOQ 仍在构建期生成 Java 代码供编译使用。

同时已经处理早期识别的上线风险：

- 生产/已有数据库默认不执行 `schema.sql`，仅在 `SPRING_SQL_INIT_MODE=always` 时重建演示库。
- JWT 密钥改为必须通过 `JWT_SECRET` 配置，不再使用默认 `secret`。
- Spring Security 日志默认降为 `info`，可通过 `SPRING_SECURITY_LOG_LEVEL` 调整。
- Redis 连接信息改为环境变量配置。
- 前端 Vite 安全漏洞通过升级 Vite 和 Vue 插件处理，并增加构建拆包配置降低大 chunk 提示风险。
