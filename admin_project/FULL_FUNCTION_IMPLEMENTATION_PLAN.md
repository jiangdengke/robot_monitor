# 管理后台全功能实现计划

本文档用于把当前重建版管理后台补齐到“原部署包已有功能全部实现”的状态。

## 目标边界

- 目标是功能 1:1：菜单、页面、按钮、弹窗、表格字段、查询条件、接口路径、权限点、初始化数据和本地可启动能力尽量与原部署包一致。
- 不追求原始仓库源码文本 1:1：当前只有部署产物，没有 sourcemap 和原始 `.vue` 文件，不能承诺恢复出原作者逐行源码。
- 真实硬件链路先不实现：机器人真机、视觉设备、语音生成服务、外部 AI 模型、Kafka 真实消息链路允许保留本地 mock 或空实现。
- 外设相关接口不能 404/500：即使先 mock，也要保证后台页面能打开、按钮能提交、接口能返回可解释结果。

## 完成标准

- `[ ]` 原后台有的菜单，当前 `frontend/src` 都有对应路由和 `.vue` 页面。
- `[ ]` 原后台有的列表页，当前都补齐查询条件、表格列、分页、字典显示、刷新和重置。
- `[ ]` 原后台有的新增、编辑、详情、删除、批量删除、导入、导出、上传、授权、预览按钮，当前都有对应交互。
- `[ ]` 原后台调用过的接口，当前后端都能返回成功；外设接口可返回 mock 成功。
- `[ ]` `backend/sql/init.sql` 覆盖所有页面启动所需表结构和示例数据。
- `[ ]` `cd admin_project/backend && ./gradlew compileJava` 通过。
- `[ ]` `cd admin_project/frontend && npm run build` 通过。
- `[ ]` 核心接口矩阵、代表性写入烟测和前端菜单打开检查通过。

## 原部署包功能来源

当前计划基于以下来源整理：

- `frontend/legacy-dist/static/js/*.js` 中提取出的页面 chunk、接口路径和权限点。
- `frontend/legacy-dist/static/css/*.css` 中保留的页面样式线索。
- `backend/src/main/java` 和 `backend/src/overlay/java` 中已反编译/覆盖的 Controller、Service、Mapper。
- 当前 `frontend/src/views` 中已重建的页面源码。
- 当前 `backend/sql/init.sql` 中已重建的表和示例数据。

## 优先级

1. 系统管理和系统监控先补齐，因为它们是后台基础框架。
2. 配置管理第二优先，因为数字孪生、餐食、旅客等依赖配置数据。
3. 餐食、旅客、航班、统计第三优先，保证业务页面完整。
4. 数字孪生、numberModel、工具模块第四优先，处理复杂交互和 mock 动作。
5. 导入导出、权限控制、全量验收最后统一收口。
