# 通用机器人管理系统

本仓库提供单体 Spring Boot 后端 `backend` 与 Vue 管理前端 `frontend`，产品范围固定为通用机器人管理。

## Structure

```text
backend/
  src/main/kotlin/        Spring Boot monolith Kotlin source
  src/main/resources/     application config and schema.sql
  build/generated-sources/jooq/  jOOQ generated Java code during Gradle builds
  build.gradle.kts
frontend/
  src/                    Vue 3 + Ant Design Vue source project
  legacy-dist/            Original built frontend assets
  package.json
  vite.config.js
docs/
  e2e-smoke.md             Current smoke-test instructions
  e2e-smoke-report.*       Reports generated by an actual smoke-test run
  generated/               Historical generated references
```

## 当前能力

- 认证、用户管理与个人资料。
- 个人头像上传与通用文件上传。
- 场地（site）、区域（area）、点位（point）三级空间模型。
- 设备管理与设备点位绑定。
- 机器人管理。
- 任务模板、任务执行与任务执行日志。
- 登录日志与操作日志。
- Swagger API 文档。

系统使用以下固定空间契约：

- API 路径为 `/config/sites`、`/config/areas`、`/config/points` 和 `/config/device-point-bindings`。
- 场地字段为 `siteId`、`siteName`、`siteCode`。
- 点位字段为 `pointId`、`pointName`，任务目标字段为 `targetPoint`。
- 已删除的旧 API、旧字段和旧前端路由不提供兼容别名；携带有效身份访问旧接口时应返回 HTTP 404。

## 工程状态

- Active backend is `backend`.
- Project-owned backend source is now Kotlin under `backend/src/main/kotlin`.
- `backend/src/main/java/org/jdk/project` no longer contains hand-written Java source. Gradle still keeps the Java plugin because jOOQ generates Java code under `build/generated-sources/jooq` during builds.
- Backend build checks can be run with:

```bash
cd backend
./gradlew test spotlessCheck
```

Full backend packaging can be verified with:

```bash
cd backend
./gradlew clean jooqCodegen compileKotlin compileJava bootJar
```

- Frontend is now based on `Vite + Vue 3 + Ant Design Vue`.
- Frontend build passes with:

```bash
cd frontend
npm run build
```

- Browser smoke-test instructions are documented in `docs/e2e-smoke.md`. Generated reports are runtime evidence and must be refreshed by a real test run rather than edited manually.
- Current API summary is documented in `backend/API_SUMMARY.md`.

## Important Boundary

- `backend` is the only maintained backend in this repository.
- `frontend/src` is maintainable reconstructed source adapted to the new monolith API.
- `frontend/legacy-dist` is preserved only as static historical reference.

## Backend Runtime

- Backend uses MySQL via `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USERNAME`, and `MYSQL_PASSWORD`.
- Startup no longer rebuilds the demo schema by default. Set `SPRING_SQL_INIT_MODE=always` only for local demo database rebuilds.
- JWT must be configured with `JWT_SECRET`; use a long random value outside local demos.
- The product is a fixed generic robot management system.
- Frontend routes and sidebar menus are defined statically in the frontend source.

## Docker Deployment

This project can be delivered as a single Docker image. The image contains:

- Nginx serving the built frontend on port `7777`
- Spring Boot backend running inside the same container on port `8080`
- Nginx proxying `/api/*` to the backend without exposing backend port `8080`

The default `docker-compose.yml` starts the application, MySQL, and Redis together. Copy `.env.example` to `.env` and set secure passwords and JWT values before the first startup. The application container serves the frontend bundled into its image; Compose does not mount or depend on a host `frontend/dist` directory.

Start or stop the complete environment with the single Compose file:

```bash
docker compose pull
docker compose up -d
docker compose down
```

For local image builds from source:

```bash
docker compose up -d --build
```

Do not commit `.env`. MySQL and Redis ports are bound to the local host only, while the application is exposed through `ROBOT_MONITOR_PORT`.
Set `JAVA_OPTS` only when the server needs an explicit JVM memory limit.
Keep `SPRING_SQL_INIT_MODE=never` for existing or production databases. Use `always` only when intentionally rebuilding demo data.
The bundled `schema.sql` sets the MySQL client connection to `utf8mb4`. Docker initialization scripts only run for an empty MySQL data volume, so recreate only the local demo MySQL volume when applying initialization-script fixes.

Pushing to `main` triggers `.github/workflows/docker-image.yml`, which builds and publishes the single image to GHCR.
